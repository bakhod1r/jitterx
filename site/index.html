jitterx

Stop your fleet from

Jitter for retries, backoff, timeouts and scheduled work in Go. Standard library only, zero allocations on the hot path.

The problem, drawn

300 clients hit a failing service at the same instant and each retries four times. Every bar is one 100 ms slice of wall clock; taller means more requests landing together.

Same number of requests in every tab. Jitter does not reduce load, it stops the load arriving all at once.

Retry a call

b := jitterx.New(
    jitterx.WithBase(200*time.Millisecond),
    jitterx.WithMaxRetries(4),
    jitterx.WithMaxElapsed(30*time.Second),
)

user, err := jitterx.DoValue(ctx, b, func(ctx context.Context) (*User, error) {
    return fetchUser(ctx)
})

Permanent(err) stops immediately. RetryAfter(d, err) lets a 429 name its own delay.

Spread periodic work

The half no retry library covers: many processes running the same schedule.

// +/- 10% by default
t := jitterx.NewTicker(30*time.Second, nil)
defer t.Stop()

for range t.C {
    refreshCache()
}

Retry every HTTP call

client := &http.Client{Transport: &jitterx.Transport{
    NewBackoff: func() *jitterx.Backoff {
        return jitterx.New(jitterx.WithMaxRetries(3))
    },
}}

Idempotent methods only, replays bodies only when it safely can, honours Retry-After, and hands back the last response instead of an error when the retries run out.

Strategies

StrategyRangeUse for
Full[0, d)Best spreading. Can retry almost instantly.
Equal[d/2, d)Half the delay guaranteed, half random.
Decorrelated[base, prev*3]Long outages, no ceiling keeping clients in step.
Proportional[d-d*f, d+d*f]Cron ticks, cache TTLs, heartbeats.
Early(d-d*f, d]Lease renewal, token refresh. Never exceeds d.
